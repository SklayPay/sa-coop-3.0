# Порт SA:COOP на GTA SA 3.0 (Steam/RGL)

## Состояние

Начата инфраструктура порта, но **3.0 пока не включена**: мод распознаёт её и выключается с
понятным сообщением. Это сделано намеренно — клиент использует 552 уникальных литеральных
адреса образа 1.0 US (плюс адреса, вычисляемые из базовых), и без записи в таблице вызов
функции или чтение глобальной переменной попадёт в чужое место.

Что уже сделано:

- определение версии `gta_sa.exe` вынесено в `src/client/shared/game/version/GameVersion.cpp`;
- все версионные адреса и сигнатуры лежат в одном месте — `src/client/shared/game/version/Addresses.cpp`;
- добавлен сканер байтовых сигнатур с wildcard-байтами (`?`) и смещением;
- `Core.cpp` больше не содержит проверку `*(uint32_t*)0x82457C`, а спрашивает `game::version::Get()`;
- добавлен инвентарь адресов `tools/port/inventory.ps1`.

- по адресу `0x85EC4A` лежит `0x94BF` — это сигнатура 3.0;
- шесть прямых адресов из `Addresses.cpp` (`0x4DE2F0`, `0x57D370`, `0x620E70`, `0x7671B0`,
  `0x77D940`, `0x82A950`) подтверждены дизассемблером по началу функций;
- шаблоны SilentPatch, предназначенные для NewSteam/RGL, на 3.0 **не подходят**: например,

  используются только прямые адреса `v30`.

## Почему публичных данных пока мало

Проверены открытые источники, в первую очередь SilentPatch — самый полный публичный проект,
который поддерживает новые бинарники. Пересечение его таблицы `AddressByVersion` с адресами
нашего клиента:

- 9 адресов из 552;
- из них прямые адреса для 3.0 есть только у 6 (остальные у SilentPatch закрыты шаблонами
  только для NewSteam/RGL).

Полной публичной карты «1.0 US → 3.0» для всех функций и глобальных переменных, которые нужны
SA:COOP, нет. Адреса в 3.0 не сдвинуты на одну константу: бинарник перекомпилирован, функции
могут быть встроены, удалены или изменены. Поэтому механически перенести 551 адрес нельзя.

Практические пути:

1. **Легальная локальная копия 1.0 US и 3.0** — извлечь сигнатуры/адреса автоматически и
   проверить их на запущенной игре. Это самый надёжный путь.
2. **Публичные базы адресов** — добавлять в `Addresses.cpp` по мере появления; сейчас их
   недостаточно.
3. **Отказ от абсолютных адресов** — постепенно переводить функции на поиск по сигнатурам.
   Это правильнее, но требует переписать места, где адрес используется как данные (смещения
   структур, глобальные массивы), и всё равно требует эталонного бинарника для проверки.

## Как добавить адрес

1. Открой `src/client/shared/game/version/Addresses.cpp`.
2. Добавь строку в `kEntries` (таблица отсортирована по `v10`):

```cpp
{"CPlayerPed::ProcessControl", 0x5E8B70, 0x0, {"55 8B EC ...", 0}, ResolveKind::Direct},
```

- `v10` — адрес в 1.0 US;
- `v30` — прямой адрес в 3.0 (если известен);
- `pattern` — байтовая сигнатура для NewSteam/RGL; для 3.0 она не используется, потому что
  подходящий по байтам фрагмент может оказаться другой функцией;
- `offset` — смещение от начала совпадения (может быть отрицательным);
- `kind` — `Direct`, `Pointer` (прочитать 32-битный указатель) или `Rel32` (пересчитать
  относительный переход).

3. Запусти инвентарь:

```powershell
powershell -ExecutionPolicy Bypass -File tools/port/inventory.ps1
```

Он покажет, сколько адресов ещё не покрыто. Для проверки в CI можно добавить
`-FailOnMissing`, когда таблица будет полной.

## Что должно быть покрыто до включения 3.0

Пока `game::version::IsSupported()` возвращает `true` только для 1.0 US. Чтобы включить 3.0,
нужно:

- заполнить `Addresses.cpp` для всех адресов, которые клиент использует в рантайме;
- перевести `mem::Hook`/`mem::Write`/`RedirectCall` и `game::Call`/`game::Ref` на
  `game::version::Resolve` (сейчас инфраструктура есть, но старый код ещё вызывает константы
  напрямую);
- проверить смещения структур (`CPed`, `CVehicle`, `CPad`, `CPlayerInfo`, пулы, камера): они
  тоже могут отличаться между 1.0 и 3.0;
- проверить script-переменные и миссии: сюжет в 3.0 может иметь другой `main.scm` и другие
  глобальные переменные;
- прогнать сюжет, машины, камеры, сохранения и вдвоём на целевой версии.
